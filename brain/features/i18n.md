# Languages

The panel reads in English or French. `[panel] language` is `auto`, `en` or `fr`;
`auto` follows `LC_ALL`, `LC_MESSAGES`, then `LANG`, and on macOS and Windows the
system's own answer when none of them is set. A language with no translation reads
in English.

- `i18n.rs` holds one table with English as the key. `tr("Today")` looks a sentence
  up, `tf!("Resets {reset}", reset = when)` fills named placeholders so a translation
  can reorder them, and a sentence with no entry reads in English.
- `load_config` applies the setting, so a daemon's reload moves the language too. The
  daemon's locale is the systemd unit's, which can differ from the desktop's, so a
  surprising `auto` is fixed by setting `language`.
- `--json` carries the table as `strings` (empty in English) and the setting under
  `panel_options`. QML reads it through `usage.t` and `root.t`, GNOME through
  `Panel.translate`. Rust frontends call `tr`.
- Dates go through `date_pattern`, because chrono's month and weekday names are
  English. A duration's day unit is `j` in French (`day_unit`).
- Every settings pane offers the option. Waybar and the TUI have no pane, so theirs
  is `config.toml`.

Not translated, on purpose or for now:

- Errors a provider or the network wrote, `--doctor`, logs and the CLI's own output.
- Model names and titles built from them, such as Claude's `Fable only`.
- Number and money formats: `$12.34` and `1.2B` stay as they are in both languages.
- The TUI's sync setup, GNOME's preferences window and Plasma's configuration dialog.
  Those last two are built without a snapshot to read the table from.

`i18n::tests` is the backstop: `every_sentence_has_a_translation` reads every source
that feeds the table, Rust, QML and TypeScript, so a new sentence with no French fails
a test.
